Depensa is an expense tracker that reads your order history from the shops you buy from and puts it all in one list, with no bank account or card to link. On Android you can get it from [Google Play](https://play.google.com/store/apps/details?id=com.techwithanirudh.depensa). It's not on the [App Store](https://www.apple.com/app-store/), so on iPhone you install it with [SideStore](https://sidestore.io/) or [AltStore](https://altstore.io/).

## How it started

The first plan looked pretty different from what shipped. You'd sign in to a shop inside a [Firecrawl](https://www.firecrawl.dev/) cloud browser, an AI would learn how to read that shop, and bank exports would get merged in too. One idea survived every rewrite though: the AI only *learns* a shop, it doesn't do the daily syncing. A model browsing on every sync costs money every time and answers a bit differently each run, so the daily path had to be plain code.

## Building it

The first big change was sign-in. Now the shop's own login page opens in a <Term>WebView</Term> on your phone, you type your password and <Term>MFA</Term> yourself, and the phone hands only the session (its cookies and `localStorage`) to the backend, which stores it encrypted. Depensa never sees the password.

The second was the backend. In September I moved everything agentic out of [Convex](https://www.convex.dev/) into a separate [Mastra](https://mastra.ai/) worker that runs on my own server (I'd already played with Mastra in my [Slack agent template](/projects/mastra_slack_agent_template)). Convex stays the database and the scheduler. The worker holds a <Term>websocket</Term> to it, claims queued runs and writes results back through mutations, so it never needs an open port.

The fun part is the reader. The first time you add a shop, a learner agent opens a cloud browser with your session and pokes around until it finds your orders.

<Mermaid
  chart="flowchart LR
  L[Learner agent] --> A{Site's own orders JSON?}
  A -- no --> B{Data blob in the page?}
  B -- no --> C{Script over order cards?}
  C -- no --> X[Can't read this site]
  A -- yes --> R[Saved reader]
  B -- yes --> R
  C -- yes --> R
  R --> S[Plain runner on a schedule]"
/>

- **Three tries, in order:** the JSON request the site makes for your orders, then a data blob baked into the page (like `__NEXT_DATA__`), then a script over the rendered order cards as a last resort.
- **Saved as data, not code:** whatever works becomes versioned JSON with one [JSONata](https://jsonata.org/) expression per field, and a plain runner replays it from then on.
- **One currency:** every order is converted to yours when it's saved.
- **Extra tricks when needed:** Blinkit's order list only has IDs, so its reader fetches each order's details too.
- **Self-healing:** when a site changes and a reader breaks, a repair agent writes a new version. The old one stays active until the new one passes a live test.
- **Honest failure:** if nothing works, the app tells you it can't read that site.

## Where it is now

It works with 100 shops across ten regions. On top of the list you can move orders between categories, set a monthly limit for a category or a shop, and ask for an email with all your expenses as a CSV. Version 1.1.0 added home screen widgets for this month, your budget and what's coming up.

Next on my list: an Expo SDK upgrade, moving the widgets onto `expo-widgets` and adding Live Activities, and learning readers for the big shops in every country ahead of time, so the first person to add one doesn't have to wait.
