A starting point for teams who want their own Slack agent instead of a hosted one. It runs as a long-lived Bun process, handles mentions, DMs, threads, files, and workspace search, and streams replies back into Slack with live tool-activity widgets instead of one blob of text at the end.

## Why it exists

Hosted Slack bots are fine until you want them to actually do something, like run a script or poke at a repo, instead of just talking. Building that yourself usually means solving sandboxing, memory, and tool orchestration before you've written a single feature. This template does that part for you, so you can point it at a Slack workspace and start adding what you actually want.

## How it works

Every thread gets its own isolated E2B sandbox, with persistent files, shell access, and a browser, so the agent can run commands and inspect files without ever touching the host machine. Bigger requests get split across subagents (orchestrator, explore, research, execute, summarize) instead of one model trying to do everything in a single pass.

Around that core sit web research through Exa, image generation, and scheduled tasks, with optional GitHub and AgentMail accounts. New capabilities go in as skills or MCP servers, so extending the agent doesn't mean forking the runtime itself.

Models are routed through OpenRouter, memory and state live in PostgreSQL, and observability runs locally. The [configuration guide](https://github.com/techwithanirudh/mastra-slack-agent-template/blob/main/docs/configuration.md) walks through setting up each service, since the template only comes alive once the Slack app and credentials exist.

## Stack

- Mastra runtime on Bun, TypeScript, and the AI SDK.
- Slack via the Chat SDK adapter in Socket Mode.
- OpenRouter models, Exa search, E2B sandboxes.
- PostgreSQL memory and state, with local observability.
